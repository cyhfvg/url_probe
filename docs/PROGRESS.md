# url_probe 开发进度

更新日期：2026-05-27

## 当前定位

`url_probe` 是一个异步 HTTP/HTTPS 端点检查命令行工具，用于在已授权范围内快速
收集端点响应状态、下载大小与 HTML 标题，并将结果导出供进一步处理。

## 已实现功能

- [x] 使用 clap 提供命令行界面及英文 `--help` 文档。
- [x] 支持单个 HTTP/HTTPS URL、URL 文件和 stdin（`--target -`）输入。
- [x] 跳过输入文件或 stdin 中的空行与 `#` 注释行。
- [x] 支持 `GET` 和 `HEAD` 请求方法。
- [x] 支持并发数、单请求超时、失败重试及自定义 User-Agent。
- [x] 支持使用单一 `--proxy <URL>` 配置 HTTP、HTTPS、SOCKS5 与 SOCKS5H 代理，
  并支持 URL 内嵌认证信息。
- [x] 支持启用或禁用重定向跟随和 HTTPS 证书校验绕过。
- [x] 采集 HTTP 状态码；`GET` 请求采集下载大小，并从 HTML 响应提取标题。
- [x] 支持仅保留指定状态码、屏蔽指定状态码和屏蔽指定响应大小。
- [x] 支持选择是否输出失败请求结果。
- [x] 支持将 CSV 或 JSON Lines 输出到 stdout 或文件。
- [x] 配置了 GitHub Actions CI 以及 Linux/Windows 发布构建工作流。
- [x] 通过 CI 配置的严格 Clippy 检查（`-D warnings`）。

## 当前行为与限制

- `--insecure` 当前默认为 `true`，即默认接受无效 HTTPS 证书；对证书有效性敏感的
  检查应显式使用 `--insecure false`。
- 输入中的无效 URL 会被跳过，目前不会在输出中单独报告。
- 请求按完成顺序写出；启用并发后，输出顺序不保证与输入顺序一致。
- `GET` 会读取整个响应体以计算大小和提取标题，大响应可能带来较高内存和流量开销。
- 代理参数仅接受 `http://`、`https://`、`socks5://` 或 `socks5h://` scheme
  URL，不提供分离的代理认证覆盖参数。
- 尚未提供请求速率限制或全局扫描预算。
- 自动化测试已覆盖代理 URL 校验与客户端构建；实际 HTTP 响应、过滤和输出行为仍
  缺少集成测试覆盖。

## 代理方案结论

- 通过 `--proxy <URL>` 设置代理，HTTP 与 HTTPS 目标流量使用同一代理配置。
- 认证信息使用 URL 用户信息形式提供，例如
  `socks5h://username:password@127.0.0.1:1080`。
- SOCKS 采用 reqwest 已支持的 SOCKS5/SOCKS5H 方案；其中 `socks5h://` 会将目标
  域名解析交给代理端，适合需要避免本地 DNS 解析的场景。
- 未增加 `-x` 短选项或独立的 `-U` 认证参数，避免出现两套凭据来源。

## 范围决策

- 路径字典枚举功能明确由独立工具实现；`url_probe` 继续聚焦于对给定 URL 的响应
  探测、筛选与导出，不增加路径发现或枚举职责。

## 使用边界

本工具只应对拥有所有权或获得明确授权的目标运行。操作者应根据授权范围控制并发量、
目标数量和运行频率，避免对服务造成不必要影响。
